## 3. 系统概述

### 3.1 产品定位

面向粉丝的**内容策展型展示站**：以「软木板图钉」隐喻组织虚拟歌手「明透」相关的简介、社媒、作品视频、曲表、动态推文、官方绘图等；强调沉浸式画布浏览与品牌一致的暖色视觉。

### 3.2 运行环境

- 目标客户端：现代桌面浏览器（Chrome / Edge / Firefox / Safari 等）
- 部署形态：静态资源构建产物（Vite `build`），可由任意静态托管提供

### 3.3 技术约束摘要

- 前端：Vue 3、Vue Router、Vite、原生 CSS
- 数据：构建时打包的 JSON、本地静态资源；部分页面通过 `sessionStorage` 传递跨页载荷

## 6. 非功能需求

### 6.1 性能

- 首屏应对重图片使用「全部就绪后再展示小地图」等策略，避免 minimap 尺寸严重偏差（以当前实现为准）。
- 图片墙应采用懒加载、分批测量，降低一次解码压力。

### 6.2 兼容性

- 使用标准 Web API；构建目标由 Vite 配置决定。
- 路由使用 History 模式，部署时需配置服务端回退到 `index.html`。

### 6.3 无障碍与可用性

- 关键按钮与预览层应具备 `aria-label` 等属性；加载过程可标注 `aria-busy`（以当前实现为准）。
- 触控/键盘：图片项应支持 Enter/Space 打开预览（以 `ImageWallView` 为准）。

### 6.4 安全

- 外链使用 `rel="noopener noreferrer"`；推文正文若为 HTML，信任模型由数据源决定，维护者应控制 JSON 内容。

### 6.5 可维护性

- 卡片坐标、类型、内容与 `cards.json` 及 `HomeView` 注入逻辑分离维护；曲库数据与 `data/*.json` 对齐。

## 7. 数据需求

### 7.1 卡片（概要）

每张卡片至少包含：`id`、`type`、`x`、`y`、`title`（可选）、`content`（随类型变化）、`meta`（可选）、`pin` / `layout` / `rotate` / `zIndex`（可选）等。曲库表格卡片可含 `rowDetailRouteName`、`rowDetailQuery`。

### 7.2 外部数据文件（示例）

- `codes/src/data/cards.json` — 画布静态卡片定义  
- `data/asu_music_data.json`、`data/albemuth_music_data.json` — 曲库表数据  
- `codes/src/data/debut.json` — 出道天数  
- `tweets_*.json` — 推文时间线或精选推文（路径以 `HomeView`/`TimelineView` 导入为准）  
- `codes/src/data/timeline.json` + 时间线事件 JSON — 时间轴

## 9. 验收准则（概要）

1. 访问 `/` 可进入图钉墙，能拖拽/滚轮平移，小地图在加载完成后出现且视口框跟随。  
2. 点击曲库表行可进入 `/table-row/:rowIndex?table=...`，详情字段合理；可回首页。  
3. 从官方绘图入口进入 `/image-wall` 可看瀑布流；无 payload 时有空状态。  
4. `/timeline` 可加载时间轴与搜索；可回首页。
