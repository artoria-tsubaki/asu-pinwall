# 瀑布流图片加载测试清单

## 1. 目标

本文档用于验证 `ImageWallView.vue` 中“先预取图片尺寸，再按视口插入图片”的瀑布流加载方案，判断其是否存在功能、稳定性、性能和交互上的 bug 风险。

重点关注以下风险：

- 进入页面时是否提前请求了全部图片，而不是真正懒加载
- 单张坏图、慢图、超大图是否会让页面卡在 loading
- 搜索、滚动、返回重进后，`IntersectionObserver` 和加载状态是否一致

## 2. 涉及文件

- `codes/src/views/ImageWallView.vue`
- `codes/src/components/content/ImageWallRotatingContent.vue`
- `codes/src/utils/imageWallStorage.js`

## 3. 测试准备

### 3.1 工具准备

- 打开浏览器 DevTools
- 启用 `Network`、`Performance`、`Console`
- `Network` 中关闭缓存
- 分别使用正常网络、`Fast 3G`、`Slow 3G` 进行测试

### 3.2 数据准备

准备以下 4 组测试数据：

1. 正常图集：10 到 20 张可访问图片
2. 大图图集：50 到 100 张高分辨率图片
3. 异常图集：包含 404、超慢响应、跨域受限图片
4. 混合图集：横图、竖图、超长图、超宽图、无标题图

## 4. 功能与正确性测试

### 4.1 基础打开

步骤：

1. 从图片墙入口卡片进入瀑布流页面
2. 观察页面是否正常渲染

预期结果：

- 页面正常打开
- 瀑布流区域可见
- 关闭按钮可用
- 返回逻辑正常

### 4.2 空数据

步骤：

1. 清空 `sessionStorage` 中的图片列表，或构造空数组
2. 打开瀑布流页面

预期结果：

- 显示空态文案
- 不报错
- 不出现无限 loading

### 4.3 正常图片显示

步骤：

1. 使用 10 到 20 张正常图片进入页面
2. 缓慢滚动页面直至全部图片进入过视口附近

预期结果：

- 所有图片最终都能显示
- 标题与图片对应
- 无明显错位、重叠、空白卡片残留

### 4.4 搜索过滤

步骤：

1. 输入可命中的关键词
2. 输入不可命中的关键词
3. 清空搜索关键词

预期结果：

- 结果数量正确
- 无结果时显示空态
- 清空搜索后图片恢复
- 恢复后的图片仍能继续加载

### 4.5 预览弹层

步骤：

1. 点击图片打开预览
2. 使用键盘 `Enter`、`Space` 打开预览
3. 使用 `Escape` 关闭预览
4. 点击遮罩关闭预览

预期结果：

- 预览能正常打开和关闭
- 键盘交互有效
- 没有焦点陷阱

### 4.6 下载按钮

步骤：

1. 在预览中点击下载按钮
2. 分别测试同源图和远程图

预期结果：

- 下载成功，或降级为可打开图片地址
- 不会一直处于 busy 状态
- 下载失败不会导致弹层异常

## 5. 高风险异常场景测试

### 5.1 单张 404 图片

步骤：

1. 图集中混入 1 张无效地址图片
2. 打开瀑布流页面

预期结果：

- 页面不应卡在 loading
- 其他图片仍可继续显示

### 5.2 单张超慢图片

步骤：

1. 图集中混入 1 张极慢响应图片
2. 在 `Fast 3G` 和 `Slow 3G` 下分别测试

预期结果：

- 页面不应因为等待该图尺寸而长时间白屏
- 若页面长期停留在 loading，记为高优先级风险

### 5.3 多张异常图片

步骤：

1. 同时混入 404、超慢、跨域失败图片
2. 打开页面并滚动

预期结果：

- 页面整体仍可进入可操作状态
- 异常图片不会阻断正常图片展示

### 5.4 超大图

步骤：

1. 使用多张超高分辨率图片测试
2. 观察性能和内存表现

预期结果：

- 页面可打开
- 无明显卡死
- 无明显内存暴涨或主线程长阻塞

## 6. 懒加载与性能测试

### 6.1 首屏请求数

步骤：

1. 打开页面后不滚动
2. 观察 `Network` 面板的图片请求数量

预期结果：

- 理想情况只请求首屏附近图片
- 如果一进页面就对全部图片发起请求，记录为“并非真正懒加载”

### 6.2 滚动加载

步骤：

1. 缓慢滚动到底部
2. 再快速滚回顶部

预期结果：

- 接近视口的图片优先加载
- 已加载图片不反复闪烁
- 已加载图片不会丢失

### 6.3 大图集性能

步骤：

1. 使用 50 到 100 张图片测试
2. 记录首屏可见时间、可交互时间、初始请求数、总请求数和内存占用趋势

预期结果：

- 页面仍可操作
- 没有明显卡顿
- 初始请求数与懒加载设计预期一致

### 6.4 反复进入退出

步骤：

1. 进入图片墙后立刻返回
2. 重复 5 到 10 次

预期结果：

- 页面不会持续变慢
- 没有明显请求残留
- 没有事件监听泄漏迹象

## 7. 布局与交互稳定性测试

### 7.1 不同宽度

步骤：

1. 使用手机宽度测试
2. 使用平板宽度测试
3. 使用桌面宽度测试

预期结果：

- 2 列、3 列、4 列切换正常
- 卡片不重叠
- 卡片不截断

### 7.2 极端比例图片

步骤：

1. 使用超长竖图测试
2. 使用超宽横图测试
3. 使用尺寸异常或缺失元信息的图片测试

预期结果：

- 占位比例与真实渲染后无严重跳动
- 不出现塌陷、覆盖或异常空白

### 7.3 搜索中滚动

步骤：

1. 先滚动到中后段
2. 输入搜索关键词
3. 清空搜索关键词

预期结果：

- 恢复后图片仍能按当前位置继续正确加载
- 不出现漏加载或永久空白块

### 7.4 键盘可达性

步骤：

1. 使用 `Tab` 聚焦图片
2. 使用 `Enter` 或 `Space` 打开预览
3. 使用 `Escape` 关闭预览

预期结果：

- 焦点路径清晰
- 键盘操作可完成主要流程

## 8. 结果记录模板

建议每轮测试记录以下内容：

- 测试日期
- 测试环境和浏览器版本
- 网络条件
- 测试数据集类型
- 是否通过
- 实际现象
- 控制台错误
- Network 关键截图或说明
- 风险等级：低 / 中 / 高

## 9. 验收结论口径

通过标准：

- 空数据、正常图、搜索、预览、关闭、返回均正常
- 单张异常图不会导致页面整体不可用
- 滚动加载逻辑与预期一致
- 大图集下页面仍可操作

重点风险项：

- 首屏是否全量请求图片
- 单张慢图是否导致 `dimensionsReady` 长时间不为 `true`
- 异常图是否影响其他图显示
- 大图集下是否出现明显卡顿或内存压力

## 10. 备注

当前页面数据来自 `sessionStorage`，入口来自图片墙卡片组件。此清单用于发现风险，不包含修复方案；若测试中确认存在高风险问题，再补充修复设计和回归用例。
