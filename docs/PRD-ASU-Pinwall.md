## 1. 背景与机会

### 1.1 背景

虚拟歌手「明透」相关信息分散在视频平台、社媒、百科与自有资料中。粉丝与路人需要一个**单站聚合展示**：既有记忆点（图钉墙），又能下钻到曲库详情、时间轴与图集，视觉上与既有品牌化方向（暖色 Mistral 风）一致。

### 1.2 机会陈述

用**可策展的画布 + 可跳转的二级页**承载内容更新：运营侧主要改 JSON 与静态资源即可迭代，开发与粉丝体验路径清晰。

---

## 2. 产品目标与成功标准

### 2.1 目标（Goals）

1. **G1**：用户可在 1 分钟内理解首页为「可拖动的图钉板」，并找到至少一种感兴趣的内容（视频/表/推文/图）。  
2. **G2**：想查单曲资料的用户可从表格进入详情页并获得封面、试听入口（若有）。  
3. **G3**：可按时间回顾事件的访客能使用时间轴页并完成简单检索。  

### 2.2 非目标（Non-Goals）

- 不做账号、评论、投稿或后台 CMS。  
- 不做服务端实时拉取 X/Twitter（当前为构建期 JSON；管线见内部实施计划）。  

### 2.3 成功指标（可运营化，可选）

| 指标 | 说明 | 备注 |
|------|------|------|
| 首页停留时长 | 画布参与深度 | 需埋点，当前未强制 |
| 表格 → 详情转化率 | 行点击 / 表格曝光 | 需埋点 |
| 图片墙访问率 | 从入口进入比例 | 需埋点 |

*注：若未接分析 SDK，本阶段以「功能可用 + 无阻塞性缺陷」为发布标准。*

## 3. 用户与场景

### 3.1 目标用户

- **粉丝**：熟悉艺人，想快速跳转 B 站/站外与看图。  
- **路人**：从外链误入，需要直观的简介与代表作入口。  

### 3.2 关键场景（User Stories）

1. **浏览画布**：用户打开站点 → 拖动画布浏览卡片 → 用右上角「导航」或左上角小地图快速定位。  
2. **查歌**：用户在「原创曲」或「Albemuth 投稿」表中找到一行 → 点击进入详情 → 看视频/外链。  
3. **冲浪时间线**：用户进入时间轴页 → 搜索关键词或日期标签 → 定位到某一事件幻灯片。  
4. **存图**：用户在官方绘图入口进入瀑布流 → 点开大图 → 需要时下载。

## 4. 产品范围

### 4.1 功能清单（Must / Should / Could）

| 模块 | 功能 | 优先级 |
|------|------|--------|
| 首页图钉墙 | 画布平移、边界、加载态、多类型卡片 | Must |
| 首页图钉墙 | 小地图、象限导航、侧柜卡片列表 | Must |
| 曲库 | 表格展示、行跳转详情、外链单元格 | Must |
| 曲库详情 | 封面、简介、播放器、返回 | Must |
| 官方绘图 | 入口轮播、session 传图、瀑布流、预览下载 | Must |
| 时间轴 | TimelineJS 嵌入、搜索、query 深链、返回 | Should |
| 推文卡片 | 轮播、跳转 X | Must |
| 出道天数 | 基于 debut 数据展示 | Must |

### 4.2 信息架构（页面级）

```
/                 → HomeView（图钉墙）
/table-row/:rowIndex → TableRowDetailView（曲库行详情）
/timeline         → TimelineView（时间轴）
/image-wall       → ImageWallView（官方绘图瀑布流）
```

## 5. 详细需求说明

### 5.1 首页图钉墙

- **画布**：固定逻辑尺寸与视口 clamp；支持拖拽与滚轮平移；标题栏固定不随画布移动。  
- **卡片数据**：以 `cards.json` 为主，`HomeView` 对特定 `id` 注入本地资源 URL、推文数组、插图 glob 等。  
- **导航**：小地图展示卡片色块与视口框；侧柜列出全部卡片标题并支持跳转（实现细节以组件为准）。  

### 5.2 曲库表格与详情

- **表格**：支持说明段落、表头、高亮单元格、`{ href, value }` 型链接格。  
- **行点击路由**：`rowDetailRouteName` + `rowDetailQuery` 决定 `router.push` 目标。  
- **详情页**：根据 `table` query 切换 ASU 曲库与 Albemuth 数据源；`discographyMatch` / `discographyCovers` 负责匹配封面与播放器 URL。  

### 5.3 官方绘图

- **入口**：`image-wall-teaser` 卡片，`ImageWallRotatingContent` 将 slides 写入 `sessionStorage` 再 `push` 至 `ImageWall`。  
- **详情**：列布局瀑布流、懒加载、全屏预览层；无数据文案引导用户从首页进入。  

### 5.4 时间轴

- 动态插入 `timeline.css` / `timeline.js`；`mittBus` 等与搜索组件协作；`?go=N` 跳转到第 N 张。

## 6. 内容与技术依赖

| 依赖 | 说明 |
|------|------|
| JSON 数据 | 曲库、出道、推文、时间线事件 |
| 静态资源 | 视频、头像、illus 目录图片 |
| TimelineJS | 本地静态文件，依赖 `BASE_URL` |
| sessionStorage | 图片墙跨页列表，容量与隐私需注意 |

---

## 7. 非功能需求（产品视角）

- **性能**：弱网下首屏可接受等待；大图懒加载。  
- **可发布性**：纯静态构建，适配 GitHub Pages 等。  
- **无障碍**：关键交互带 `aria-label`；路由页专注管理可走后续专项。  

---

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 推文/第三方样式变更 | 精选 JSON 由脚本定期更新；正文 HTML 需人工抽检 |
| 图片墙刷新丢失 session | 产品接受；后续可加 query 或短链恢复 |
| TimelineJS 体积与加载失败 | 超时提示；保持静态资源可缓存 |
